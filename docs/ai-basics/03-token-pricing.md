## Input, Output и Cached Tokens

При работе с LLM оплачиваются три основных типа токенов:

- **Input tokens** — всё, что отправляется модели _(запрос, System Prompt, история диалога, файлы).
- **Output tokens** — всё, что модель генерирует в ответ (текст, код и тд.)
- **Cached input** — повторяющаяся часть входного контекста, которую провайдер может использовать из кэша по сниженной цене.

## Почему Output дороже?

**Input** обрабатывается за один проход через модель.

**Output** генерируется постепенно: модель предсказывает один токен, добавляет его к ответу, затем заново вычисляет следующий токен уже с учётом всего текущего текста. Этот процесс повторяется до конца ответа.

## Как считается стоимость

Цены обычно указываются **за 1 миллион токенов**.

В зависимости от провайдера используются разные категории:

- **Input**
- **Cached Input (Cache Read)**
- **Output**
- **Cache Write** *(есть у некоторых провайдеров, например Anthropic)*

### Базовая формула

```text
Стоимость = Input + Cached Input + Output
```

## Prompt Caching

Если большая часть контекста не меняется между запросами (например, System Prompt, инструкции проекта или история чата), провайдер может использовать её из кэша.

Это позволяет не обрабатывать один и тот же контекст заново и снижает стоимость.

```
Первый запрос
↓
Контекст сохраняется в кэш
↓
Следующие запросы
↓
Используется Cached Input
```

Важно понимать, что **кэширование зависит от провайдера**. Не любой контекст автоматически становится Cached Input — сервис сам решает, какие данные можно закэшировать, как долго хранить кэш и когда его обновлять.

## Пример цен (GPT-5.5)

|Тип токенов|Цена за 1 млн|
|---|---|
|Input|$5|
|Cached Input|$0.5|
|Output|$30|

Если запрос содержит:

- Input — **100 000** токенов
- Output — **5 000** токенов

Стоимость составит:

```
Input:
100 000 / 1 000 000 × $5 = $0.50

Output:
5 000 / 1 000 000 × $30 = $0.15

Итого: $0.65
```
